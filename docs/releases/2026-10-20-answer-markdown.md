# 2026-10-20：新旧回答统一 Markdown、表格与公式展示

## 根因与实现

旧 `ChatPanel.FormattedContent` 只通过正则拆分反引号代码，其他 Markdown 一律输出成普通 span；没有表格或数学解析，也没有对应公式字体。不是模型没有生成格式。

`dace46b` 删除旧 formatter，统一使用 `AnswerMarkdown`：CommonMark、GFM 表格/列表/引用/链接、remark-math 与 KaTeX。样式只作用于回答，使用现有主题颜色；宽表、长代码与独立公式在自身区域横向滚动，不撑破消息。KaTeX CSS 与实际解析依赖版本对齐，字体由本应用构建产物提供，不请求外部公式服务。架构参见 [React Markdown 官方示例](https://github.com/remarkjs/react-markdown#use-remark-and-rehype-plugins-math)。

同时支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；对反斜杠形式做代码感知的规范化，不改代码块/行内代码。`2519349` 补齐 Windows CRLF 代码围栏后的公式恢复。原始消息不改写，复制和导出仍为原始 Markdown；用户输入保持纯文本，原生思考继续在独立区域保留原文，不能冒充正文。流式更新采用延后渲染与 memo，旧消息不因监控轮询重复解析。

不启用原始 HTML；危险 URL 受过滤，外链使用 noreferrer/noopener，不自动加载模型生成的远程图片（只显示说明），KaTeX 不信任 HTML/链接扩展并限制宏展开。未闭合/未知公式或半截表格不让整页崩溃，也不编造缺失内容。并非任意无分隔符 TeX 或格式错误的 Markdown 都能被无损猜测修复。

## 旧回答与本机会话

现场确认旧版消息只在 React 内存中，刷新会丢失；不能声称所有历史都已在服务端保存。本次增加按标签页隔离的 sessionStorage 恢复及本机 JSON 导入/导出。导入和刷新恢复本身不请求模型，不覆盖原文、不重新生成答案；用户之后继续提问时，才按正常上下文发送历史。没有新增服务端会话归属或自动认领机制。

保存过程去抖，关闭/刷新页面时补保存；存储满或不可用会明确提示，不能静默截断。生成中刷新后按中断状态恢复，不标成功或自动继续。导入校验版本、角色、字段和重复 ID，拒绝不支持数据；10 MiB 以上文件明确拒绝，不截断。浏览器关闭、无痕窗口销毁或站点存储被清理后，sessionStorage 不保证保留，需提前导出；旧版已经丢失且没有备份的内存记录不能凭空找回。

验收不是生成一份“看起来像旧回答”的假样本：先用 Chrome 保存当前旧公网窗口（真实 09:43/09:45 两轮），再以不执行脚本/不加载资源的离线工具提取其可见原文。`scripts/archive_saved_chat.mjs` 保留四条消息、原时间、独立思考及实际 4803/2190 token。页面没有保存上游终态，不为档案编造终态。工具初版曾将相邻分钟和 token 数连读，已修正为独立 span 严格匹配，并由 `1d213b8` 增加回归；错误档案未作为最终通过证据。

该 DOM 迁移工具仅接受保留完整原文的旧页面；旧 formatter 已剥离代码语言/围栏的 pre/code 内容明确拒绝有损转换，需用原始响应或已有 JSON 档案恢复。无论何种历史来源，主渲染器均支持原始代码围栏；不能为了“旧内容已修好”编造丢失的语言标记。
